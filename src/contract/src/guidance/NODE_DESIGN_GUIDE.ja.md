# カスタムノードの設計

Quollio Topology は QDIC のクラスを専用のアイコンで描画します。それ以外のすべてのノードタイプでは、あらかじめ決められたアセットに頼らず、`types` でノードを自分で設計してください。タイプごとに 1 回だけ宣言します。

    "types": {
      "<node type>": { "label": "Supplier", "rank": 1, "color": "#5b6b8c", "abbr": "SU", "glyph": "<svg path d>" }
    }

## 1. 形は階層に従う
まずデータの階層を推論し、次にタイプごとにランクを付けてください。ランクが上がるほど辺の数が増えます。

| rank | 形               | 用途                                               |
|------|------------------|----------------------------------------------------|
| 0    | circle           | データポイントの最小単位 (リーフ、レコード)           |
| 1    | triangle         | 1 つ上の階層: 単位をまとめる、または生み出すもの      |
| 2    | square / diamond | コンテナ。同じ階層の兄弟クラスには diamond を選ぶ      |
| 3    | pentagon         | コンテナからなるシステムまたはドメイン                |
| 4–6  | hexagon → octagon | 階層の最上位                                       |

階層がないときは、すべてのタイプにランク 0 (circle) を使ってください。形を階層以外の意味に使わないでください。

## 2. サイズはランクで決まる
サイズは自由ではありません。ランク 0 は 20px で、ランクが 1 上がるごとに 6px 増え、ランク 6 で 56px になります。階層が高いほど大きく表示されます。サイズは送信しないでください。

## 3. グリフ、なければ 2 文字
タイプに分かりやすいピクトグラムがあるときは、`glyph` として送信してください。24×24 の枠に収まる SVG の path `d` を 1 つ、線のみで書きます (Lucide のアイコンと同じ)。ないときは `abbr` として、そのタイプを表す 2 文字のローマ字を送信してください (SUpplier → SU、KPI → KP)。1 つのペイロード内のすべてのタイプで、文字を変えてください。

## 4. 色は自由、コントラストは自由ではない
どの色相でもかまいません。彩度の高すぎる色は避けてください。レンダラーは彩度を 55% に制限します。ノードは明るいキャンバス (#F4F4F5) と、中間トーンのエッジから際立つ必要があります。中程度に濃いトーンを選んでください。キャンバスとのコントラストが 3:1 未満の色はレンダラーが暗くし、ノード上の文字は白またはインクの読みやすいほうにします。関連するタイプには近い色相を、無関係なタイプには異なる色相を与えてください。

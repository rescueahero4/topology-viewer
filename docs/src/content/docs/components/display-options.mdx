## Options

| Part | Option | Does |
|---|---|---|
| `scope-menu` | `budgets` | The choices, such as `[25, 100, "all"]` |
| `scope-menu` | `default` | The first choice |
| `layout-menu` | `layouts` | The built-in layouts to keep: `force`, `atomic`, `bubbles`, `tree-h`, `tree-v` |
| `layout-menu` | `default` | The first layout, or `custom:<name>` |
| `grouping-menu` | `values` | The choices, such as `[3, 8, "off"]` |
| `grouping-menu` | `default` | The first choice |

<Aside type="note">
A `view` in the payload wins over `default`, so that your data can decide its own first view.
</Aside>

## Your own layout

`layouts` adds a layout to the menu. Its name is `custom:<key>`. It is a pure function: the same graph gives the same places. Look for **Ring** in the layout menu.

<Demo name="custom-layout" height={460} />

`run` gets the drawn nodes, each with `id`, `type`, `label`, `width` and `height`, and the edges, with `source`, `target` and `predicate`. It returns `{ [id]: { x, y } }`. A node with no place stays where it is.

```tsx
import dagre from "@dagrejs/dagre";

<TopologyViewer
  layouts={{
    dagre: {
      label: "Layered",
      run: ({ nodes, edges }) => layOutWithDagre(nodes, edges),
    },
  }}
  parts={{ "layout-menu": { options: { default: "custom:dagre" } } }}
/>;
```

## Reorder and add

`items` sets the bar. A name keeps a default menu, leaving one out removes it, and `{ id, render }` adds yours.

```tsx
parts={{
  "display-options": {
    items: [
      "layout-menu",
      "scope-menu",
      { id: "export", render: ({ commands }) => <ExportButton state={commands.getState()} /> },
    ],
  },
}}
```

To remove one menu and keep the order, use `"grouping-menu": { hidden: true }`.

## Drive it from your code

```tsx
viewer.current?.setLayout("tree-v");
viewer.current?.setBudget(25);
viewer.current?.setGrouping("off");
```
